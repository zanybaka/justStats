## Phase 18 — Network monitoring (2026-11-21, approved mockup)

- [ ] NET-008 Cut the Network tab's idle cost (about 1% CPU while on screen)
Task Context
NET-006 measured the Network tab at about 1.0% CPU with both disclosures collapsed (1.4-1.5% expanded) and 32-34 MB footprint, against 0.0% / 24-25 MB for the default Disks tab; a tick of the data path alone is about 0.4 ms (0.04% at 1 Hz), so the cost is the once-per-second SwiftUI re-render. Suspects: `NetSampler` publishes four properties per tick (`samples`, `latest`, `totals`, `interfaces`), each firing `objectWillChange`, so the card and the interfaces list rebuild several times per second; the Canvas sparkline redraws 180-point paths for two series every tick; `NetworkInterfacesView` and the card both observe the whole sampler. Fix by publishing one value per tick (a single struct) and by letting views observe only what they draw, then re-measure with the NET-006 method (same throwaway open-on-launch patch, `top -l 61`, Network open collapsed and expanded).
Task DOD
Network tab, both disclosures collapsed, measured at or below 0.3% average CPU over 60 samples on the same machine (or the remaining cost explained with a profile); the Disks tab and the closed popover unchanged; unit tests for the sampler's publishing still green; TECHSPEC section 7 updated with the new numbers.
