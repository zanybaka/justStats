## Phase 17 — Volume list refinements (2026-11-21, live feedback)

- [ ] VOL-008 Eject button per volume: on refusal, name the holder in human language (DiskArbitration dissenter)
Task Context
Live feedback: macOS 'wasn't ejected because one or more programs may be using it' never names the blocker, and the owner had to run diagnostics to learn it was mds_stores. Design (approved by owner 2026-11-21): eject glyph button on external/network volume rows (HoverFillButtonStyle, hover reveal; never on the boot volume or internal fixed disks). Flow: DADiskUnmount via DiskArbitration (framework already linked for BSD names; no sudo, no lsof parsing). On success the row leaves the list: VolumeListViewModel starts observing NSWorkspace.didUnmountNotification (it does not today). On dissent the completion callback carries a DADissenterRef; DADissenterGetPID + proc name feed a built-in dictionary mapping known system holders to short English UI phrases per PRD (UI is English-only): mds_stores -> Spotlight indexing, usually releases in a minute or two; rsync -> file copy in progress; backupd -> Time Machine backup; Finder -> Finder has this disk or its files open; photoanalysisd -> Photos analyzing. Unknown PID falls back to honest 'process <name> (PID <n>)'. The inline panel under the row (same pattern as the trash inline confirmation) offers Retry and Force Eject; force re-issues the unmount with kDAOptionForce and always warns when the holder may be writing. A multi-volume stick ejects the whole device like Finder: all volumes of the disk unmount, and a refusal names both the volume and the holder. PRD currently forbids this feature (out-of-scope list includes eject; FR9 'No whole-volume actions'): this task amends PRD (drop eject from the excluded list, new FR, ADR-CANDIDATE for the DiskArbitration dissenter seam) and TECHSPEC. Eject seam is a protocol (mockable like VolumeInfoProviding); the Transcend stick currently held by mds_stores is the manual test rig.
Task DOD
Eject button renders on external and network rows and never on the boot volume or internal fixed rows (unit test on row/view-model state); a successful unmount drops the row without reopening the popover (unit test via a didUnmount notification through the seam); a dissent produces the inline panel with the holder phrase: every dictionary entry maps to its phrase and an unknown PID renders 'process <name> (PID <n>)' (unit tests on the mapper); Retry re-issues the plain unmount and Force, after its warning, re-issues with the force option (unit tests through the seam); PRD drops eject from the excluded whole-volume list, gains the new FR and the ADR-CANDIDATE, TECHSPEC documents the dissenter seam; manual check with a held flash drive shows the holder phrase and a clean eject removes the row.
