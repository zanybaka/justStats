Task Context
Live feedback: a mounted .dmg renders as an external volume row, but the row is pure noise. Free space on a read-only volume never changes, Move to Trash cannot work there, and dmg mounts are usually not Spotlight-indexed so the breakdown shows the degraded not-indexed state. Verified on macOS 15 (live probe of a mounted dmg): it reports volumeIsReadOnly=true (plus removable=true, ejectable=true, isInternal=nil), while writable volumes report false. Implement via NSURLVolumeIsReadOnlyKey (macOS 10.7+): add isReadOnly: Bool? to VolumeInfo, prefetch .volumeIsReadOnlyKey in FileManagerVolumeInfoProvider (prefetchKeys + identityKeys), and drop volumes with isReadOnly == true in VolumeEnumerator.isUserFacing. Fail open: nil/unknown keeps the volume visible, we hide only what provably cannot change. Do NOT key on DiskArbitration disk-image markers (DAMediaName, DADeviceModel): the criterion is read-only-ness, not image-ness, so read-write images (sparsebundle backups) stay visible.
Task DOD
Volumes with isReadOnly == true yield neither an internal nor a deferred entry (unit test via the VolumeInfo seam, next to the existing DiskImage fixture in VolumeEnumeratorTests); isReadOnly == nil still shows (fail-open, unit test); isReadOnly == false with ejectable=true still classifies as external and renders (regression guard for sparsebundle backups, unit test); docs/prd.md In Scope/Assumptions states the read-only exclusion (line 'other mounted volumes' currently implies all mounts are shown).
